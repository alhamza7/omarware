```

┌─────────────────────────────────────┐

         │

         │
         └─ غير موجود؟
                  │
                  ↓
┌─────────────────────────────────────┐
│ 2️⃣ ابحث عن سعر الوحدة الأساسية    │
│    في Pricelist                     │
└─────────────────────────────────────┘
         │
         ├─ موجود؟ ──→ 🧮 احسب بالمعامل
         │                 السعر × (factor الهدف / factor الأساس)
         │
         └─ غير موجود؟
                  │
                  ↓
┌─────────────────────────────────────┐
│ 3️⃣ استخدام list_price              │
│    (ملاذ أخير)                      │
└─────────────────────────────────────┘
```

## 📖 أمثلة عملية

### مثال 1: سعر محدد موجود

```
المنتج: [ADF00005] المعشوق
UoM المطلوب: 0.5 كيلو
الكمية: 1

الخطوات:
1. ✅ يبحث عن سعر محدد ل "0.5 كيلو" في Pricelist
2. ✅ يجد: $22.00
3. ✅ يستخدمه مباشرة → السعر النهائي: $22.00

لا يتم الحساب بالمعامل!
السعر المحدد له الأولوية!
```

### مثال 2: سعر محدد غير موجود

```
المنتج: [ADF00005] المعشوق
UoM المطلوب: 2 كيلو (جديد، لا يوجد له سعر)
الكمية: 1

الخطوات:
1. ❌ لا يوجد سعر محدد ل "2 كيلو" في Pricelist
2. ✅ يبحث عن سعر "كغم" (الوحدة الأساسية)
3. ✅ يجد: $13.25
4. 🧮 يحسب: 13.25 × (2.0 / 1.0) = $26.50
5. ✅ السعر النهائي: $26.50

تم الحساب بالمعامل تلقائياً!
```

### مثال 3: في Sales Order

```
السيناريو:
- فتح Sales Order جديد
- اختيار منتج: المعشوق
- اختيار UoM: 0.25 كغم بلاستك
- الكمية: 10

النتيجة:
✅ السعر: $12.00 (من Pricelist مباشرة)
✅ الإجمالي: $120.00

تغيير UoM إلى: 3 كيلو (غير موجود)
النتيجة:
🧮 السعر: $39.75 (محسوب: 13.25 × 3)
✅ الإجمالي: $397.50
```

### مثال 4: في POS

```
السيناريو:
- فتح POS Session
- إضافة منتج: المعشوق
- اختيار UoM: 0.5 كيلو

النتيجة:
✅ السعر يظهر تلقائياً: $22.00
✅ من Pricelist مباشرة
✅ لا حاجة لإدخال يدوي!
```

## 🎓 فهم النظام بعمق

### متى يُستخدم السعر المحدد؟

```python
# شرط استخدام السعر المحدد:
if rule.product_uom_id and rule.product_uom_id.id == uom.id:
    # يوجد في Pricelist قاعدة محددة لهذا UoM بالضبط
    return rule.fixed_price  # ✅ استخدمه!
```

**مثال:**
```
Pricelist Item:
├─ Product: المعشوق
├─ UoM: 0.5 كيلو       ← محدد!
└─ Price: $22.00

عند طلب "0.5 كيلو":
✅ مطابقة تامة → يستخدم $22.00
```

### متى يُحسب بالمعامل؟

```python
# شرط الحساب بالمعامل:
if specific_price is None:  # لم يُوجد سعر محدد
    # ابحث عن سعر الوحدة الأساسية
    base_price = find_base_uom_price()
    # احسب النسبة
    ratio = target_uom.factor / base_uom.factor
    # السعر النهائي
    return base_price * ratio
```

**مثال:**
```
Pricelist Item:
├─ Product: المعشوق
├─ UoM: كغم            ← الأساسي فقط
└─ Price: $13.25

عند طلب "2 كيلو":
❌ لا يوجد سعر محدد ل "2 كيلو"
✅ يوجد سعر ل "كغم" = $13.25
🧮 يحسب: 13.25 × (2.0 / 1.0) = $26.50
```

## 📊 مقارنة: قبل وبعد

### قبل النظام الذكي

```
المشكلة:
├─ الأسعار المحددة قد تكون خاطئة
├─ لا يوجد fallback للحساب التلقائي
├─ يجب إدخال سعر لكل UoM يدوياً
└─ إذا نسيت UoM → خطأ أو سعر صفر!

مثال:
UoM: 3 كيلو (غير موجود في Pricelist)
النتيجة: ❌ خطأ أو $0.00
```

### بعد النظام الذكي

```
الحل:
├─ الأسعار المحددة لها الأولوية
├─ Fallback تلقائي للحساب بالمعامل
├─ يمكن خلط الأسعار المحددة والمحسوبة
└─ لا يوجد UoM بدون سعر!

مثال:
UoM: 3 كيلو (غير موجود في Pricelist)
النتيجة: ✅ $39.75 (محسوب تلقائياً)
```

## 🐛 استكشاف الأخطاء

### المشكلة 1: السعر لا يتغير عند تغيير UoM

**السبب المحتمل:**
- Cache في المتصفح

**الحل:**
```
1. Ctrl+F5 لتحديث الصفحة
2. أو امسح cache المتصفح
3. أعد فتح Sales Order
```

### المشكلة 2: السعر دائماً $0.00

**السبب المحتمل:**
- لا يوجد سعر في Pricelist للوحدة الأساسية
- list_price = 0

**الحل:**
```
1. تحقق من list_price للمنتج
2. أو أضف سعر للوحدة الأساسية في Pricelist
```

### المشكلة 3: الحساب غير دقيق

**السبب المحتمل:**
- Factors غير صحيحة في UoM

**الحل:**
```
1. Sales → Configuration → Units of Measure
2. تحقق من factor لكل UoM
3. صحح الـ factors
4. أعد الاختبار
```
